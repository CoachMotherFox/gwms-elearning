# GWMS eLearning Engine

A browser-based course engine for the **eLearning component of Block 4** in Grappling With My Self — a 36-session trauma-informed grappling program for adolescent boys.

Plain HTML, CSS and JavaScript. No database, no build toolchain, no dependencies, no backend. It runs by opening `engine/index.html` from disk, or by hosting the folder on any static file server.

This is not the Instruction Rating Form (that stays a separate tablet form) and it does not replace the in-person lesson.

---

## Running it

**Hosted (what you'll use while authoring):**

```bash
python3 -m http.server 8000
```

Then open `http://localhost:8000/engine/`. Course JSON is fetched live, so a save-and-reload shows your edits immediately.

**From disk (double-click):** open `index.html` at the project root, or `engine/index.html`. Browsers block `fetch()` on `file://` URLs, so this path reads a bundled copy of each course instead. Regenerate the bundles whenever you hand the folder to someone:

```bash
sh tools/bundle.sh
```

**Load a specific course:** `engine/index.html?course=session-02`. Defaults to `session-01`.

**Check every course before a hand-off:**

```bash
node tools/check.js
```

Exits non-zero if any course has an accessibility or integrity error. `tools/check.js` runs the same validator the engine runs at load time, so nothing can pass in one place and fail in the other.

## Structure

```
index.html            redirect to the engine (so the folder opens by double-click)
/engine
  index.html          loads a course and renders it
  /css/engine.css     one stylesheet, tokenised, light + dark
  /js
    util.js           DOM helpers, screen-reader announcements
    storage.js        sessionStorage for learner work, localStorage for prefs
    validate.js       accessibility + integrity checker, contrast audit
    slides.js         slide type registry, block renderer, interactions
    navigation.js     flat slide order, branching, history, contents menu
    app.js            boot, course loading, preferences, dialogs, keyboard
/courses
  index.json          one line per session, drives the "All sessions" list
  /session-01
    course.json       the source of truth for that session
    course.bundle.js  generated by tools/bundle.sh — do not hand-edit
    /assets
  /engine-demo        test harness, not curriculum. Delete it if you like.
/tools
  bundle.sh           wraps each course.json for file:// use
  check.js            command-line accessibility + integrity check
/docs
  DESIGN-RATIONALE.md how each build decision maps to the AECT rubric
  MODULE-STRUCTURE.md what a session module contains, and why
/courses/_curriculum      transcribed curriculum fields (not read by the engine)
```

Content model mirrors Articulate Storyline — **Course → Scenes → Slides → Interactions** — not for file compatibility, but because it's a proven structure and it keeps that door open.

## Authoring a course

Session modules are generated from the transcribed curriculum:

```bash
node tools/build-sessions.js
```

Edit `courses/_curriculum/*.json`, re-run, then `sh tools/bundle.sh`. See [docs/MODULE-STRUCTURE.md](docs/MODULE-STRUCTURE.md).

A one-off course is a folder with a hand-written `course.json`. Run `node tools/check.js` when you're done.

```json
{
  "id": "session-02",
  "title": "Session 2 — …",
  "lang": "en",
  "rightsHolder": "Grappling With My Self (GWMS)",
  "meta": {
    "session": 2, "neighborhood": "The Descent", "week": 1, "theme": "…",
    "probingQuestion": "…", "tlo": null, "elos": []
  },
  "scenes": [
    { "id": "scene-id", "title": "Scene title", "slides": [ … ] }
  ]
}
```

Any key starting with `_` (`_todo`, `_scope`, `_note`) is ignored by the engine. Use them for authoring notes — nothing in them reaches a learner. `meta.tlo` and `meta.elos` render nothing when null or empty, so an unfinished session never shows placeholder text to a boy.

### Every slide

| Key | Meaning |
|---|---|
| `id` | Unique across the whole course. Required. |
| `type` | `text-image`, `video`, `reveal`, `branch`, `quiz`, `reflection` |
| `title` | Becomes the `<h1>` and the Contents entry. |
| `eyebrow` | Small label above the title. Defaults to the scene title. |
| `body` | Array of content blocks (below). |
| `next` | Slide id to go to instead of the following slide. `null` ends the path. |
| `required` | `true` locks Next until the slide is complete. |
| `reveals` | Click-to-reveal interactions. |
| `alternates` | Other ways to take in the same content (below). |

### Content blocks

```json
{ "kind": "lead",      "text": "Opening line, slightly larger." }
{ "kind": "paragraph", "text": "Body text. **bold**, *italic*, `code` work." }
{ "kind": "heading",   "text": "Subhead", "level": 2 }
{ "kind": "list",      "items": ["one", "two"], "ordered": false }
{ "kind": "quote",     "text": "…", "attribution": "…" }
{ "kind": "callout",   "label": "Where this sits", "text": "…" }
{ "kind": "image",     "src": "assets/x.jpg", "alt": "…", "caption": "…", "own": true }
```

Blocks accept a plain string as shorthand for a paragraph.

### Images

`alt` is mandatory. A purely decorative image needs `"alt": "", "decorative": true` — the engine will not let you omit alt by accident.

Every image needs either `"own": true` (original GWMS material) or a `credit` block:

```json
"credit": { "holder": "…", "title": "…", "licence": "CC BY 4.0", "url": "https://…" }
```

Credits render under the image and are collected into **Contents → Credits & licences**.

### Slide types

**`text-image`** — `body`, optional `image`, optional `imagePosition: "after"`.

**`video`** — file-based or embedded. A transcript is required either way.

```json
"video": {
  "src": "assets/clip.mp4", "captions": "assets/clip.vtt",
  "credit": { … },
  "transcript": [ { "kind": "paragraph", "text": "…" } ]
}
```
For a hosted video use `"embed": "https://www.youtube.com/embed/…"` instead of `src` (YouTube URLs are rewritten to the no-cookie host), and set `"captionsProvided": true` once you've confirmed the hosted copy has real captions.

**`reveal`** — a slide built around disclosures.

```json
"reveals": [
  { "label": "How the roles switch", "content": [ { "kind": "paragraph", "text": "…" } ] }
]
```
With `"required": true` on the slide, Next unlocks once every reveal has been opened.

**`quiz`**

```json
{
  "type": "quiz",
  "assessment": { "role": "formative" },     // or "summative"
  "question": "…",
  "select": "single",                        // or "multiple"
  "retry": true, "maxAttempts": 2,
  "requireCorrect": false,
  "options": [
    { "text": "…", "correct": true, "feedback": "why this is right" },
    { "text": "…", "feedback": "why this one isn't" }
  ],
  "correctHead": "…", "correctText": "…",
  "incorrectHead": "…", "incorrectText": "…", "revealText": "…"
}
```
Feedback is immediate and per-option. On a wrong first attempt only the learner's own choice is annotated — the correct answer is held back until they get it or run out of attempts, so "Try again" means something.

**`reflection`** — captured, never scored.

```json
{ "type": "reflection", "prompt": "…", "hint": "…", "placeholder": "…", "required": true }
```

**`branch`**

```json
{
  "type": "branch",
  "question": "…",
  "options": [
    { "id": "a", "text": "…", "sub": "…", "target": "slide-id", "feedback": "…" }
  ]
}
```
Targets must resolve to real slide ids — a dead target is a hard error, not a runtime surprise. Back returns to the decision point, not to whatever slide happens to sit above in the file.

### Alternate representations

Any slide can offer the same material another way. The learner gets a "Take this in" control.

```json
"alternates": [
  { "mode": "audio", "label": "Listen", "src": "assets/x.m4a", "transcriptIsBody": true, "own": true }
]
```

`transcriptIsBody: true` means the slide's written text *is* the script, so it stays on screen under the player. Otherwise supply a `transcript` array. If the media file is missing the engine says so in words and leaves the text path intact.

## What the engine will not let you ship

Run on every course load, and by `node tools/check.js`:

- an image with no `alt` (or empty `alt` not declared decorative)
- a video with no transcript, or a file-based video with no captions track
- a quiz with no correct option, or a multi-correct quiz not marked `"select": "multiple"`
- a branch option pointing at a slide that doesn't exist
- duplicate slide ids, unknown slide types, unresolvable `next`
- a course using only one assessment strategy (warning)

**Contents → Accessibility check** shows the same list inside the engine, plus a live colour-contrast measurement of the current slide in whatever theme and text size the learner has chosen.

## Notes

- Bump the `?v=` on the `<link>` and `<script>` tags in `engine/index.html` when you deploy changed CSS or JS, so browsers don't serve a stale copy.
- Learner work lives in `sessionStorage` and is gone when the tab closes. Display preferences live in `localStorage`. Both are erasable from **Contents → Your data**.
- Out of scope for Phase 1, by decision: SCORM/xAPI export, a visual authoring UI, accounts, and any analytics.
